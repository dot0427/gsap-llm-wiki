# loop / graph 設計

%%GRAPH%%

## 流程說明
| 節點 | 做什麼 | 會重複嗎？ |
|---|---|---|
| ① 取得資料 | 挑官方文件，記到 `raw/sources.md` | 每篇來源一次 |
| ② 先討論 | LLM 讀完先丟 3 個問題：我在乎什麼？跟現有頁衝突嗎？ | 🔁 Ingest loop（×6） |
| ③ 寫來源頁 | 重點＋討論結論 | 🔁 Ingest loop |
| ④ 更新概念頁 / index / log | 每條事實**行內**標 [S#] | 🔁 Ingest loop |
| ⑤ Lint | 斷連結、孤兒頁、缺來源、預設值一致、來源沒講的不准寫 | 失敗 → 回 ④ 🔁 |
| ⑥ Query | 「新手該照什麼順序學？」→ 存成 synthesis | 一次 |
| ⑦ 大綱＋claim 對應 *(v2 新增)* | 每頁簡報先列「要講的句子 ↔ Wiki 哪一行」 | 對不到 → 回 ⑥ 或補 Wiki 🔁 |
| ⑧ 生成 HTML 簡報 | 照大綱寫，每頁標 data-wiki | |
| ⑨ 自動檢查 | data-wiki 對得到、API/ease/屬性都在 Wiki、瀏覽器 0 錯誤 | 失敗 → 回 ⑧ 🔁 |
| ⑩ 人工看畫面 | 截圖檢查語意、版面、demo | 失敗 → 回 ⑧ 🔁 |

## 為什麼這樣設計
- **Ingest 是迴圈**：每篇新資料都可能改到舊頁面（例：S6 解決了 S1 留下的「要不要錢？待查」），所以一定要「寫完 → 回頭更新概念頁 → 記 log」繞一圈。
- **Lint 放在生成簡報之前**：Wiki 是簡報唯一的知識來源，Wiki 錯了簡報一定錯，所以先把 Wiki 洗乾淨。
- **檢查分兩層**：自動檢查便宜、快，但只看得到「字」；人工檢查慢，但看得到「意思」和「畫面」。兩層都要。
